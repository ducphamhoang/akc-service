## Critical Issues

### C1 — Race Condition in `apply_confidence_delta` (Read-Modify-Overwrite)
**Severity:** CRITICAL - Lost Updates
**Files:** `akc_service/learning_integration.py` (line 539-635)

**Problem:**
```python
# Unsafe sequence:
load_all_patterns()           # No lock
mutate patterns in-memory
save_all_patterns()           # open('w') - full overwrite, no lock
```

- Worker A loads 200 patterns, updates pattern X to 0.55
- Worker B loads 200 patterns, updates pattern Y to 0.40
- Worker A saves (writes X:0.55)
- Worker B saves (truncates, writes Y:0.40) ← LOST UPDATE on X

**Impact:** Confidence updates are lost under concurrent load

**Fix:** Either use `append_pattern_version()` per updated pattern, or wrap entire section in `fcntl.LOCK_EX`

### C2 — `save_all_patterns` Is Not Atomic
**Severity:** CRITICAL - KB Corruption on Crash
**Files:** `akc_service/learning_integration.py` (line 163-168)

**Problem:**
```python
def save_all_patterns(patterns: list) -> None:
    with open(PATTERNS_PATH, "w", encoding="utf-8") as f:  # CRASH HERE = partial file
        for p in patterns:
            f.write(json.dumps(p) + "\n")
```

- Crash or SIGKILL mid-write leaves file in partial state
- No recovery path - next startup fails to load patterns
- `sync/state.py` does this correctly with write-to-temp + rename

**Impact:** Process crash = KB corruption + manual intervention required

**Fix:** Write to `.tmp` file first, then atomic `os.replace(tmp, target)`

---

### C3 — Quarantine Escape Hatch Does Not Block Writes
**Severity:** CRITICAL - Safety Control Broken
**Files:** `akc_service/safety_engine.py` (line 321-326)

**Problem:**
- `set_escape_hatch("quarantine")` is documented as "no KB modifications"
- Enforced in `route_fix()` (blocks fix candidates)
- NOT enforced in `append_pattern_version()`, `save_all_patterns()`, `log_confidence_update()`
- A `/record` call still writes to KB even when quarantine is active

**Impact:** Quarantine mode is broken - operator thinks writes are stopped but they're not

**Fix:** Add check at top of write functions: `if load_safety_state()["escape_hatch"] == "quarantine": raise`

## Medium Issues

### M1 — `fcntl` Is POSIX-Only (No Windows Support)
**Severity:** MEDIUM - Deployment Blocker
**Files:** `akc_service/learning_integration.py` (line 24)

**Problem:**
- `import fcntl` raises `ModuleNotFoundError` on Windows
- Will block cross-platform CI or future Windows deployment
- Project is macOS-only today but this is a future issue

**Impact:** Can't deploy on Windows

**Fix:** Conditional import or use cross-platform library (`filelock` package)

---

### M2 — `make_history_id` Has Second-Granularity Collisions
**Severity:** MEDIUM - Audit Trail Degradation
**Files:** `akc_service/learning_integration.py`

**Problem:**
- Formats to `%Y-%m-%dT%H%M%S` (second precision)
- Live KB already has duplicate `history_id` values
- Bulk operations update multiple patterns in same second → duplicate IDs
- Breaks audit trail uniqueness guarantee

**Impact:** Can't deduplicate or replay audit trail reliably

**Fix:** Use microsecond precision `%f` or `uuid.uuid4()`

---

### M3 — `signature_hash` in `/fix` Endpoint Is Unused
**Severity:** MEDIUM - Dead API Surface
**Files:** `akc_service/api/routes.py` (line 97, 429-466)

**Problem:**
- `FixRequest.signature_hash` is required in schema
- Endpoint accepts and logs it
- Filtering logic only uses `category`, not `signature_hash`
- Hash is never matched against `pattern.signature_hash`

**Impact:** API surface misleads callers - they think they can filter by hash but can't

**Fix:** Either implement hash filtering or remove the field from schema

---

### M4 — `time_window` in `/stats` Endpoint Is a No-Op
**Severity:** MEDIUM - Broken Feature
**Files:** `akc_service/api/routes.py` (line 486)

**Problem:**
- `GET /akc/v1/stats?time_window=24h` accepts and validates parameter
- Docstring says "not yet filtered"
- Always returns all-time data regardless of requested window
- Caller monitoring SLA gets wrong time range

**Impact:** Operators get incorrect SLA data (all-time instead of last 24h)

**Fix:** Either implement time_window filtering or remove parameter

---

### M5 — No Input Size Bounds on `/record`, `/sync/receive`
**Severity:** MEDIUM - DoS Vector
**Files:** `akc_service/api/routes.py`

**Problem:**
- `SyncReceiveRequest.patterns` is `list` with no `max_items` constraint
- `RecordRequest.akc_context` is `Dict[str, Any]` with no depth/size validation
- Can send unbounded JSON arrays
- Under <50ms latency budget this is a DoS vector

**Impact:** Unbounded input can cause memory spike or timeout

**Fix:** Add `Field(max_length=...)` to list fields, add depth validation for dicts

---

### M6 — `check_latency` Reads Full History File on Every `/stats` Call
**Severity:** MEDIUM - O(n) Performance Degradation
**Files:** `akc_service/api/routes.py`

**Problem:**
- `confidence_history.jsonl` is append-only with no compaction
- Every `/stats` call loads entire file from disk, line-by-line, and sorts
- No pagination, no cursor, no caching
- For 40 lines now, but by 10,000 entries this is >100ms per call

**Impact:** SLA will be breached as KB grows

**Fix:** Add pagination, cursor-based iteration, or in-memory cache with dirty flag

---

### M7 — `get_active_patterns` Scans All Patterns Linearly on Every `/query`
**Severity:** MEDIUM - O(n) Scaling Issue
**Files:** `akc_service/api/routes.py` (line 51-66)

**Problem:**
- Full linear scan of `patterns.jsonl` on every `/query`
- No index, no cache, no deduplication before filtering
- Duplicate IDs from append-only design mean same pattern appears many times
- All duplicates filtered and added to results, last one wins silently

**Impact:** Latency scales O(n) with KB size, SLA will be violated

**Fix:** Build in-memory index `{id: [versions...]}` or use `find_pattern_by_id` semantics (last occurrence only)

---

### M8 — Pydantic V2 Deprecation Warnings (3 Active)
**Severity:** MEDIUM - Technical Debt
**Files:** `akc_service/api/routes.py`

**Problem:**
- `class Config` in `QueryRequest`, `PatternResponse`, `QueryResponse` are deprecated

**Impact:** Future Pydantic upgrade will fail

**Fix:** Replace `class Config` with `model_config = ConfigDict(...)` (5 min fix)
