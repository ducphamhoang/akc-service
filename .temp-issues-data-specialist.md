# Data Specialist Review - Critical & Medium Issues

**Review Date:** 2026-05-05
**Agent:** Data Specialist
**Rating:** 2.5/5 (Not production-ready for multi-agent/concurrent traffic)

## Critical Issues

### C1 — Dual Write Path: Destructive Overwrite Races with Append-Only Path
**Severity:** CRITICAL - Data Loss
**Files:** 
- `akc_service/learning_integration.py` (line 100-113, 163-168)
- `akc_service/learning_engine.py` (line 112-116, 157-246)

**Problem:**
- `append_pattern_version()` uses `open('a')` + `fcntl.LOCK_EX` (correct append-only)
- `save_all_patterns()` uses `open('w')` (full file overwrite with NO file lock, NO atomic rename)
- `apply_confidence_delta()` calls destructive `save_all_patterns()` as FastAPI background task
- If concurrent appends happen, the full overwrite silently deletes appended entries

**Impact:** Full KB data loss without error

**Fix:** Unify write strategy - use append-only for all hot paths via `append_pattern_version()`

---

### C2 — `update_fix()` Mutates `fix_history.jsonl` In-Place Without Lock
**Severity:** CRITICAL - Data Loss
**Files:** `akc_service/safety_engine.py` (line 71-95)

**Problem:**
- Described as append-only but uses read-modify-write without file lock
- Opens with `open('w')`, creating same race condition as C1
- Can silently lose concurrent entries

**Impact:** Fix history corruption during concurrent operations

**Fix:** Convert to append-only (new entries) instead of in-place mutation

---

### C3 — Quarantine Escape Hatch Not Enforced in Write Paths
**Severity:** CRITICAL - Safety Bypass
**Files:** `akc_service/safety_engine.py` (line 321-326)

**Problem:**
- `set_escape_hatch("quarantine")` sets flag but nothing checks it
- `append_pattern_version()`, `save_all_patterns()`, API routes never read `safety_state.json`
- KB writes continue even when quarantine is "active"

**Impact:** Escape hatch is advisory-only, quarantine mode is broken

**Fix:** Add guard at top of write functions to check and enforce quarantine flag

---

## Medium Issues

### M1 — `history_id` Collision at Second-Level Precision
**Severity:** MEDIUM - Audit Trail Degradation
**Files:** `akc_service/learning_integration.py`

**Problem:**
- `make_history_id()` uses `%Y-%m-%dT%H%M%S` (second precision only)
- Live KB already has 16 duplicate `history_id` values in 40 entries
- When multiple patterns updated in same second, all get same ID
- Breaks deduplication and audit trail uniqueness

**Impact:** Audit trail loses reliable unique record identifiers

**Fix:** Change to microsecond precision `%f` or append `uuid4().hex[:8]`

---

### M2 — Tier/Confidence Inconsistency in Live KB (47 of 49 Entries)
**Severity:** MEDIUM - Safety Guard Mismatch
**Files:** `akc_service/learning_engine.py`

**Problem:**
- 47 of 49 entries have `confidence_tier` that doesn't match `confidence` value
- Boundary inconsistency: `> 0.85` vs `>= 0.85` between different functions
- Gold-tier guardrail protection doesn't apply to patterns at exactly 0.85
- Seeder doesn't call tier classifier on write

**Impact:** Gold-tier guardrail silently fails for patterns at boundary values

**Fix:** Normalize tier on write, unify boundary checks to `>=` everywhere

---

### M3 — Version Number Ceiling at v5 Is Inconsistent
**Severity:** MEDIUM - Data Freeze
**Files:** `akc_service/learning_engine.py`

**Problem:**
- `version_pattern()` hard-stops at v5 with error
- `learning_integration.py` and `routes.py` use unbounded arithmetic increment
- No enforcement between the two paths
- Pattern at v5 stops receiving updates silently

**Impact:** Patterns get stuck, learning is frozen for frequently-updated patterns

**Fix:** Replace version lookup dict with uniform arithmetic, remove v5 cap or enforce everywhere

---

### M4 — `save_all_patterns()` Not Atomic
**Severity:** MEDIUM - Data Corruption on Crash
**Files:** `akc_service/learning_integration.py` (line 163-168), `learning_engine.py` (line 112-116)

**Problem:**
- Truncates file with `open('w')` then writes lines
- Crash mid-write leaves file partial/empty with no recovery
- `sync/state.py` and `safety_escape_hatches.py` do it correctly (write-to-tmp + atomic rename)

**Impact:** KB corruption requires manual recovery on process crash

**Fix:** Use write-to-temp + atomic rename pattern from `sync/state.py`

---

### M5 — `confidence_history.jsonl` "Immutability" Only Partially Enforced
**Severity:** MEDIUM - Audit Trail Integrity
**Files:** `akc_service/safety_engine.py`

**Problem:**
- Claim is "immutable/append-only" but no enforcement mechanism
- `set_escape_hatch()` logs escape events into same file, mixing semantics
- No inode flags, no hash chaining - any code with write access can overwrite

**Impact:** Audit trail can be silently modified

**Fix:** Add enforcement (file permissions, hash chain, or separate files)

---

### M6 — `load_all_patterns()` Reads Without Lock, No Snapshot Isolation
**Severity:** MEDIUM - Stale/Partial Reads
**Files:** `akc_service/learning_integration.py`

**Problem:**
- No read lock when loading KB
- Concurrent append during read may be included partially or missed entirely
- Append-only design partially mitigates but full-overwrite path (C1) makes it worse
- Missed entries then get deleted on next save

**Impact:** Stale or partially-loaded pattern sets during queries

**Fix:** Use consistent snapshot - either lock during read or use copy-on-read

---

## Summary

**Must fix for reliability:** C1, C2, C3, M4 (all race condition/data loss vectors)
**Must fix for safety guardrails:** C3, M2 (quarantine, tier consistency)
**Nice to fix:** M1, M3, M5, M6 (audit trail, consistency, atomicity)
